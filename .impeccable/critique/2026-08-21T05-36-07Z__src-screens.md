## Design Specificity Verdict

**Authored in content, interchangeable in chrome — roughly 60/40.**

**LLM assessment:** The data model is unmistakably for Deadheads — eras named by keyboardist tenure ("Primal Dead", "Peak Keith", "Brent Era", `src/constants/tags.ts:74-86`), lineage chips ("Betty Board", "Charlie Miller"), "also on Dick's Picks" cross-refs, Taper's Compendium notes, Next Tour Stops, source pinning that only commits after a successful load. The full player (fractal video, 32px title, venue as red link, velocity-aware swipe-down, graded haptics) is the one screen that could only be this product. But the shell is the Spotify-dark kit: `#121212` ground, `#2a2a2a` cards, one red accent, Inter body, 5-tab Ionicons bar, heart-to-save, pill filters (`src/constants/theme.ts:16-64`). On the Shows list Cornell '77 and Soldier Field '95 render identically — no era, no visual signal. Only `FamiljenGrotesk-SemiBold` is loaded (`App.tsx:75`) while the type scale asks for 700, so headings are faux-bold.

## Overall Impression

The bones of a great Deadhead app are here — the taxonomy, the source picker, the search, the full player. What's missing is feedback and finish at the moments that matter most: tapping a track gives you a Play icon and silence for 1–4 seconds, errors dead-end with raw messages, and the setlist — the single artifact every Deadhead reads — is a flat list with no Set 1 / Set 2 / Encore. The single biggest opportunity: make the Shows list and setlist carry the same confidence the full player already has.

## What's Working

1. **A domain-native data model made visible.** Eras by keyboardist, lineage chips, "also on Dave's Picks Vol. 29", Taper's Compendium notes with citation, Next Tour Stops, and a source-pin that only commits after the recording actually loads (`ShowDetailScreen.tsx:353-358`). Nobody copying a music-app template ships this.
2. **Search that speaks Deadhead** (`HomeScreen.tsx:62-118`): "5/8/77", "May 8", "calif", "Dick's Picks" all resolve. Alex's 60-second task is met by typing a date.
3. **The full player** (`FullPlayer.tsx`): fractal video + gradient + clear type hierarchy + 64px disc + velocity-aware swipe-to-dismiss + graded haptics (light/medium/heavy). Peak-end works in the app's favour — sessions end here.

## Priority Issues

**[P1] No buffering state at stream start**
- **Why it matters:** The highest-stakes tap in the app ("did that work?") gets the least feedback. `LOAD_TRACK` sets `isLoading:true` without touching `isPlaying` (`PlayerContext.tsx:43-56`); MiniPlayer shows a Play glyph (`MiniPlayer.tsx:145-149`); no `ActivityIndicator` exists in MiniPlayer, TrackItem, or FullPlayer. Radio prefetch takes 13–15s after load (console). Users double-tap, skip, or assume it's broken.
- **Fix:** Render a spinner in the mini-player button and pulse the pressed row while `state.isLoading`; after ~3s show "Still loading from archive.org…"; on failure offer "Try another recording" using the ranked version list you already have.
- **Suggested command:** /impeccable harden

**[P1] Core controls invisible or phantom to assistive tech**
- **Why it matters:** Full-player prev/play/next (`FullPlayer.tsx:565-591`) have no `accessibilityRole`/`Label`/`State` — VoiceOver sees Close/Share/Rate/+/heart but not transport. Every track row renders two 28×28 ghost buttons at `opacity:0` that are tappable and announced ("Add to playlist", "Add to favorites") while the visible path is an undiscoverable long-press `Alert` (`TrackItem.tsx:54-57,114-160`, `ShowDetailScreen.tsx:410-425,834-835`). `OfficialReleaseBadge` is a button nested inside the card button (`ShowCard.tsx:116-181`, `HorizontalShowCard`) — confirmed by hydration errors. Profile avatar, search toggle, sort options, year buttons, version rows all lack roles/labels. Tab labels are 10px.
- **Fix:** Reuse `PlayerControls` (already labelled, `PlayerControls.tsx:39-79`) inside FullPlayer; return `null` for hidden track actions on native and expose a visible "…" overflow or swipe action; lift the badge out of the pressable; add roles/labels to the listed controls; bump tab labels to 11–12px.
- **Suggested command:** /impeccable audit

**[P1] Load errors are dead ends with raw messages**
- **Why it matters:** `HomeScreen.tsx:296-297` renders `ErrorState` without `onRetry`; `ShowDetailScreen.tsx:342,516-517`, `SongListScreen.tsx:116`, `ResetPasswordScreen.tsx:48` surface raw `err.message`. On a flaky train connection the app simply stops. "Couldn't play that track" (`PlayerContext.tsx:786`) names the problem but not the fix.
- **Fix:** Always pass `onRetry`; map errors to plain copy ("Couldn't reach archive.org. Check your connection."); on detail, add "Try a different recording" that calls `handleVersionChange` with the next ranked version.
- **Suggested command:** /impeccable harden

**[P2] Contrast, tap targets, and three controls for one action**
- **Why it matters:** Detector-confirmed: white on `#e54c4f` = 3.8:1 on "Start Radio" and every release badge; `#666` on `#121212` = 3.3:1 on player metadata; 10px body text in Settings. Home sort button measures 108×18 (`HomeScreen.tsx:372-382`); track stars 46×16 + hitSlop ≈ 32pt (`TrackItem.tsx:92-105`); 23px badge. Same "sort" action is a text label on Home, a pill on Favorites; Feed hand-rolls segmented tabs (`FeedScreen.tsx:84-101,152-181`); mobile web gets a centered desktop modal for the filter tray while native gets fullscreen (`ShowsFilterTray/index.tsx:199-217`).
- **Fix:** Darken the accent-on-red text or use a deeper red for filled surfaces; 44pt minimums on sort/stars/badge; one `SortPillButton` everywhere; `SegmentedTabs` in Feed; fullscreen tray under 768px.
- **Suggested command:** /impeccable polish

**[P2] The setlist has no sets, and the Shows list has no era**
- **Why it matters:** `ShowDetailScreen.tsx:815-845` is a flat `tracks.map`. Set 1 / Set 2 / Encore is the one grouping every Deadhead expects, and the "→" segue is the most Dead-specific visual there is — currently a plain character. On the Shows list every row is identical regardless of era, so the product's best idea (era taxonomy) is invisible until you open the filter tray.
- **Fix:** Infer set breaks (IA track-number gaps, Drums/Space anchors, encore position) and render headers; draw segues as connected rows; give the Shows list an era tint or era label per row, with the date as the primary typographic key.
- **Suggested command:** /impeccable shape

## Persona Red Flags

**Casey (distracted, one-handed):** Sort, filter and search all live in the top 94px of Home — out of thumb reach. Can't favorite from the list: mobile cards have no save button (`ShowCard.tsx:203` is desktop-only) and the Favorites empty state tells her to "Tap the save button on any show" (`FavoritesScreen.tsx:417-418`), a control that doesn't exist on her phone. Sort/filter state is component-local on native (`HomeScreen.tsx:135-148`) — lost on relaunch after an interruption. Buffering gives no sign of life, so she taps again. Wins: mini player and Apply are in the thumb zone.

**Jordan (first-timer):** "Matrix · 1.5M views" with a chevron is the only explanation of source selection; "Low Generation 1893", "16-Track 19", "Betty Board 68" are undefined in the tray (definitions exist only in `sourcePreferences.ts:15-19`). Filter is an `options-outline` icon with no label; sort is plain text with no affordance; rewind/previous is a secret double-tap; three hollow stars in the player read as "rated low" against a 5-star mental model.

**Sam (screen reader / low vision):** Transport controls absent from the a11y tree; phantom track actions announced; profile button unlabeled in every header (`ScreenHeader.tsx:65-74`, `FeedScreen.tsx:41-51`, `SongListScreen.tsx:217-226`); search expand/close unlabeled (`AnimatedSearchBar.tsx:126-132`); `YearButton` and Select all/Clear all have no role/state (`YearsSection.tsx:52-61,125-132`); VersionPicker rows have no selected state (`VersionPicker.tsx:61-67`); toast auto-dismisses in 4s with no live region (`ToastContext.tsx:63-65`); 3.3–3.8:1 contrast on badges, stars and metadata; 10px tab labels; full player is not a modal to AT.

**Alex (power user):** Must open detail to play; no queue/up-next; no 15/30s seek; source switch is a fullscreen modal per change; Reset-instant vs Apply-deferred asymmetry in the tray; no "shuffle this show" / "play from here". Wins: date search, pinning, deep links, "Use default".

## Questions to Consider

1. This is a setlist app that renders setlists as flat lists — where are Set 1 / Set 2 / Encore, and the segue as structure rather than a "→" character?
2. Source selection is the signature feature, yet the pill is the last element in the header and "Matrix · 1.5M views" is all a newcomer gets. What if the recording choice were the hero of Show Detail?
3. Five peer tabs for a product whose core loop is "find show → play". Could Songs fold into search and Feed into Profile, leaving three?
4. Why do the three riskiest moments (tap track, buffering, stream failure) get the least feedback while filter pills get haptics?
5. The full player is the only screen that feels like Scarlet>Fire. What would the Shows list look like if it borrowed that confidence — era-tinted rows, date as the primary key, venue as secondary?
